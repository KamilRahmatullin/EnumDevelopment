## ✨ Возможности

EnumDevelopment — утилита для администраторов и разработчиков, которая позволяет искать и править
конфигурации сервера **не выходя из игры**. Все задачи выполняются асинхронно, показывают прогресс,
результаты можно выгрузить в YAML, а замены — откатить одной командой.

| | |
|---|---|
| 🔍 **Поиск текста** | Найти слово, фразу или фрагмент JSON во всём дереве папок |
| ♻️ **Замена текста** | Переписать совпадения на месте, с резервной копией перед каждой записью |
| 🎒 **Поиск предмета** | Найти предмет из основной руки в YAML-секциях, списках и Base64-строках |
| 🔁 **Замена предмета** | Заменить предмет из основной руки на предмет из второй руки везде, где он встречается |
| ↩️ **Отмена** | Восстановить файлы, изменённые последней заменой |
| 📄 **Отчёты** | Сохранить полные результаты в `plugins/EnumDevelopment/results/*.yml` |

## 🎮 Команды

```text
/ed find    "слово или фраза"         /plugins [-s] [-n имя] [-f]
/ed find    'JSON или фраза с "'      /plugins [-s] [-n имя] [-f]
/ed replace "старая фраза" "новая"    /plugins [-s] [-n имя] [-f]
/ed replace 'старый JSON' 'новый'     /plugins [-s] [-n имя] [-f]
/ed finditem                          /plugins [-s] [-n имя] [-f]
/ed replaceitem                       /plugins [-s] [-n имя] [-f]
/ed undo
/ed reload
/ed help
```

`/enumdevelopment` работает как алиас для `/ed`.

### 🚩 Флаги

| Флаг | Назначение |
|---|---|
| `-s` | Сохранить полный отчёт в YAML-файл |
| `-n` / `-name` | Имя файла отчёта — расширение `.yml` добавляется автоматически |
| `-f` | Перезаписать существующий файл отчёта |

## 🎒 Поиск и замена предметов

`/ed finditem` ищет в файлах предмет, который игрок держит в **основной руке**.
`/ed replaceitem` ищет предмет из основной руки и заменяет его предметом из **второй руки**.

Поддерживаемые форматы хранения предметов:

- YAML-секции `ItemStack` Bukkit/Spigot, в том числе вложенные — `resultItem`, `item1`, `items.0`.
- YAML-списки Bukkit/Spigot с сериализованными записями, например `Inventory.Main: - ==: org.bukkit.inventory.ItemStack`.
- Вложенные карты и списки внутри YAML — для плагинов, которые хранят инвентари как обычные YAML-коллекции.
- Base64-строки с одним `ItemStack`, массивом `ItemStack[]` или распространённым форматом инвентаря с префиксом размера.

Обе команды асинхронны и принимают те же флаги отчёта, что и текстовый поиск. `replaceitem` открывает
сессию отмены, поэтому `/ed undo` восстанавливает файлы, изменённые последней заменой предметов.

**Связанные настройки**

```yaml
settings:
  item-search:
    match-amount: false              # игнорировать количество в стаке при сравнении
    scan-base64: true                # декодировать и сканировать Base64-строки
    preserve-amount-on-replace: true # сохранять количество, уже записанное в файле
    base64-min-length: 48            # минимальная длина строки, считающейся Base64
```

При `preserve-amount-on-replace: true` можно держать во второй руке один предмет и переписывать только
*данные* предмета, не трогая количество в конфигах. Поставьте `false`, если количество из второй руки
должно перезаписывать старое.

## ↩️ Отмена

Перед перезаписью файла каждая успешная `/ed replace` и `/ed replaceitem` делает лёгкую резервную копию.
Последнюю замену можно откатить командой:

```text
/ed undo
```

Данные отмены хранятся в `plugins/EnumDevelopment/undo/`; старые сессии удаляются согласно
`settings.undo.max-sessions`.

## 💬 Парсер кавычек

Аргументы можно оборачивать в двойные **или** одинарные кавычки. Для JSON и MiniMessage-подобных строк,
в которых уже есть двойные кавычки, удобнее одинарные:

```text
/ed replace '{"bold":false,"color":"white","text":"Эффективность"}' '{"bold":false,"color":"#ED78FF","text":"Эффективность"}' plugins/ -s -n enchant_replace -f
```

Поддерживается экранирование `\"`, `\'` и `\\`.

## 🔎 Поведение поиска

Поиск и замена всегда выполняются вне основного потока, сообщения о прогрессе включены по умолчанию.

По умолчанию сканируются только распространённые текстовые/конфигурационные расширения, а тяжёлые папки
(кэши, логи, бэкапы, базы данных) пропускаются. Чтобы сканировать все расширения:

```yaml
settings:
  allowed-extensions:
    - "*"
```

Для поиска без учёта регистра:

```yaml
settings:
  case-sensitive: false
```

## ⚙️ Конфигурация

`config.yml` разделён на `settings`, `flags` и `messages`. Основные параметры:

| Ключ | По умолчанию | Описание |
|---|---|---|
| `max-depth` | `32` | Максимальная глубина обхода каталогов |
| `ignored-directories` | кэши, логи, бэкапы… | Имена папок, которые полностью пропускаются |
| `allowed-extensions` | `.yml`, `.yaml` | Расширения для сканирования; `"*"` — все |
| `case-sensitive` | `true` | Учитывать регистр при текстовом поиске |
| `max-chat-results` | `15` | Сколько совпадений выводится в чат |
| `max-stored-results` | `100000` | Совпадений в памяти / в отчёте |
| `max-active-tasks` | `16` | Одновременных задач поиска |
| `max-file-size-kb` | `8192` | Файлы больше этого размера пропускаются |
| `follow-symbolic-links` | `false` | Переходить ли по символическим ссылкам |
| `search-binary-files` | `false` | Сканировать ли бинарные файлы |
| `allow-outside-server-directory` | `false` | Защита, удерживающая пути внутри папки сервера |
| `result-directory` | `results` | Папка отчётов внутри папки данных плагина |
| `charset` | `UTF-8` | Кодировка чтения и записи файлов |
| `progress.*` | вкл., 1000 файлов / 3000 мс | Частота сообщений о прогрессе |
| `undo.*` | вкл., `undo`, 10 сессий | Папка и глубина хранения сессий отмены |

Весь вывод в чат задаётся в `messages:` и поддерживает `&`-коды и hex-цвета `&#RRGGBB`.

## 🔨 Сборка

Требования: **JDK 8+** и **Maven** в `PATH`.

```bash
mvn clean package
```

Готовый плагин появится по пути:

```text
target/EnumDevelopment-1.0.5.jar
```

## 🛡️ Защищённая сборка

Защищённая сборка переносит основную логику плагина в `META-INF/enum.payload`: классы переименовываются,
а сам payload шифруется AES-256-GCM. В открытом JAR остаётся только
`com.enumdev.enumdevelopment.Main` и его служебные классы загрузчика.

```powershell
.\build-protected.ps1
```

`build-protected.bat` — обёртка, запускающая тот же скрипт.

Требования: **Maven** и **JDK 17+** (`java` и `javac` из одной установки) для инструмента упаковки —
ASM 9.7.1 загружается через Maven автоматически. Итоговый плагин по-прежнему сохраняет Java 8 bytecode
и API 1.16.

> [!WARNING]
> `target/EnumDevelopment-<версия>-mapping.txt` позволяет деобфусцировать защищённую сборку.
> Храните его приватно и никогда не коммитьте.

## 🗂️ Структура проекта

```text
src/main/java/com/enumdev/enumdevelopment/
├── Main.java              # инициализация плагина и загрузчик payload
├── commands/              # исполнитель /ed, таб-комплит, регистрация
├── config/                # слой доступа к config.yml
├── internal/              # точка входа для защищённой сборки
├── managers/              # задачи поиска, хранение результатов, сессии отмены
├── models/                # параметры поиска, результаты, отчёты, записи отмены
├── services/              # движок поиска по файлам
│   └── item/              # сравнение предметов, Base64-кодек, поиск предметов
└── utils/                 # парсер аргументов, пути, цвета, сообщения

src/main/resources/        # plugin.yml, config.yml
tools/                     # обфускатор и упаковщик payload (защищённая сборка)
build-protected.ps1/.bat   # конвейер защищённой сборки
```
